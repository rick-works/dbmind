# 提示词目录

这个目录里的 `*.md` 就是 AI 各场景实际使用的提示词，**改完重启应用即生效，不用重新编译**。

## 加载顺序

1. 程序内置的默认值（随安装包分发）；
2. **本目录里的同名文件会覆盖内置值** —— 也就是你现在看到的这些。

首次启动时，程序会把内置默认值释放到这里（只补缺失的文件，不会覆盖你改过的内容）。
所以：

- 想改某个提示词：直接编辑对应文件，重启应用；
- 想恢复某个提示词的默认值：**删掉那个文件**，重启后会自动重新释放一份；
- 新版本新增的提示词：升级后会以缺失文件的形式自动补齐。

## 文件与功能的对应关系

| 文件 | 用在哪 |
|---|---|
| `common.default-system.md` | 对话的默认人格（未指定场景提示词时使用） |
| `common.brevity.md` | 通用简洁性约束，拼接在 system 末尾 |
| `sql.explain.system.md` / `sql.explain.user.md` | 编辑器「AI 解释」 |
| `sql.optimize.system.md` / `sql.optimize.user.md` | 编辑器「AI 优化建议」 |
| `sql.fix.system.md` / `sql.fix.user.md` | SQL 执行失败后的「错误分析与修复」 |
| `sql.rewrite.system.md` / `sql.rewrite.user.md` | 「语义等价重写」（要求结果集一致） |
| `command.parse.system.md` / `command.parse.user.md` | Ctrl+K 命令面板：自然语言 → 操作计划 |

## 模板变量

提示词里的 `{{变量名}}` 是运行时动态填入的内容，例如：

- `{{schemaContext}}`：相关表结构（由程序按当前连接自动检索后填入）
- `{{sql}}`：待处理的 SQL
- `{{error}}`：数据库返回的错误信息
- `{{goal}}` / `{{command}}` / `{{context}}` / `{{tables}}` / `{{targetSections}}`：各场景自有的上下文

**注意**：变量名不要改、不要删（程序会报「缺少变量」并明确告诉你是哪个），
报错信息里会同时列出当前允许的变量名。

## 有「输出契约」的提示词，改之前先看一眼

这几个提示词的输出会被程序解析，不只是给人看的：

- `sql.fix.*`：必须输出「错误原因：…」和「修复SQL：…」两行，程序按这两行拆分；
- `sql.rewrite.*`：只输出裸 SQL（不要 Markdown 代码块）；
- `command.parse.*`：只输出严格 JSON，且 `type` 只能取提示词里列出的动作名。

改这些时保持输出格式不变，否则对应功能会拿不到结果。
