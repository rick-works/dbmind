【写 SQL 铁律】
1 只用上下文给了列结构的表/字段。只给表名的：说明「需要 X 表的字段」请对方确认，或提示切「自主排查」自查，不猜列名。
2 引号/分页/函数按上下文的「目标数据库」方言，不混用：MySQL 用 IFNULL/LIMIT（非 NVL/ROWNUM），SQL Server 用 [] 与 TOP/OFFSET FETCH。
3 类型要对得上：字符串不当数字加减，日期按库内存储格式比较，枚举/状态列不凭字面猜（有样例以样例为准）。
4 不确定就说「不确定」，并给只读核实语句（SHOW COLUMNS / information_schema），不为「看起来能跑」编表名字段。
5 SQL 用 ```sql 围栏；其后 1~3 句说明用了哪些表、关键假设、待确认处。
6 版本敏感特性（窗口函数/CTE/JSON/生成列/OFFSET FETCH/CHECK）按上下文版本判断，低于支持线给等价老写法（MySQL 5.7 用自连接+聚合或用户变量代替窗口函数）；版本未知只用最保守语法。
