# v1.0.4

> 后台任务不再「永远停在收尾」—— 卡住会被**如实报出来**，而不是无限期挂着

发布日期：2026-10-09
类型：修订版（缺陷修复，不含破坏性变更）

## 数据传输

- **修掉「任务永远停在后台收尾」**：真机现象是任务跑了 21 分钟，界面提示
  「任务仍在后台收尾，已允许关闭窗口」，关掉窗口、点停止都没用 —— 刷新回来它还在。
  进程侧一看：宿主 Java 进程 **0% CPU、一条数据库连接都没有**，也就是说它不是在慢慢跑，
  而是卡在一处永远不返回的等待上。
- **根因**：`cancel()` 只是一个标志位，工作体要在**分页 / 分批之间**才查得到它。一旦工作体
  卡在某个等待上（最典型：网络切换、对端掉线之后），这个检查点永远走不到，任务就永远
  停在 `running`，前端只能一直轮询。
- **修法（真实截止时间，而不是启发式猜）**：
  - 数据库调用这一层**本来就有硬截止时间** —— 内核发给宿主的是 `timeoutMs + 2s`，超时即
    `QueryTimeout`；用户取消还会经 `Statement.cancel()` 打到驱动。
  - 缺的是**流水线内部的交接**：读侧交出刚读到的一页、写侧取走一批、收尾等协程结束、
    多对象并发等槽位。这些 `send().await` / `handle.await` / `acquire().await` 原先都没有
    截止时间。现在它们统一带 660 秒的截止时间（比单次数据库调用的上限 600 秒再宽一点，
    所以正常的慢不会被误杀 —— 正常的慢只会慢在**调用**上，不会慢在"没人来取数据"上）。
  - 超时后任务以**具体原因**结束，例如
    「写入侧 11 分钟没有取走数据，判定下游已停止（连接可能已断开）」，而不是笼统地"卡住"。
- **兜底看门狗**：万一某条路径仍无任何进展（新写的循环、别的任务类型、我们自己的锁等待），
  30 分钟后强制结束并落 `error`，日志里会写明「这条路径缺少截止时间，请把本行反馈给开发」
  —— 它同时是保险与「该修哪里」的探针。已写入的部分保留，不回滚。

## 安装包（全平台）

按平台与使用习惯挑一个即可 —— **每个包都自带精简 Java 运行时**，装完就能连库，不必另装 Java。

| 平台 | 文件 | 形态与适用场景 | 大小 |
|---|---|---|---|
| Windows | DBmind_1.0.4_x64-setup.exe | 安装向导（推荐） | 46.3 MB |
| Windows | DBmind_1.0.4_x64_en-US.msi | MSI 包（企业批量部署 / 静默安装） | 53.4 MB |
| Windows | dbmind-1.0.4-portable.zip | **免安装**：解压即用，不写注册表，可放 U 盘 | 63.7 MB |
| macOS（Apple 芯片） | DBmind_1.0.4_aarch64.dmg | 安装镜像：拖进「应用程序」 | 52.1 MB |
| macOS（Intel） | DBmind_1.0.4_x64.dmg | 安装镜像：拖进「应用程序」 | 53.8 MB |
| Linux（Debian / Ubuntu） | DBmind_1.0.4_amd64.deb | apt 安装，带开始菜单项 | 64.9 MB |
| Linux（通用发行版） | DBmind_1.0.4_amd64.AppImage | **免安装**：`chmod +x` 后直接运行 | 137.2 MB |

- 免安装版的用法就两步：Windows 解压后运行 `start.bat`；Linux 给 AppImage 加执行权限后直接跑。
- macOS / Linux / Windows 三个平台由同一套流水线、同一份源码打出，彼此功能一致。
- **本版三个平台的包都未签名**：macOS 首次打开需到「系统设置 → 隐私与安全性」放行，
  Windows 安装时会提示「未知发布者」—— 选择"仍要运行"即可，不影响功能。

## 升级提示

- 无破坏性变更，直接升级即可
- 如果 1.0.3 那次传输被你中途关掉过，建议用 **merge / upsert 模式**把那几张表重跑一遍：
