# v1.2.1

> 修一个会让 macOS 版**双击就打不开**的问题：安装包里带着一条指向 Homebrew OpenSSL 的绝对路径，目标机器上没有它就崩在启动那一刻

发布日期：2026-10-10
类型：修订版（无新功能、无破坏性变更，建议所有 macOS 用户升级）

## 症状

macOS（实测 M1）双击 `DBmind.app` 立即退出，系统弹「问题详细信息」，关键几行是：

```
Termination Reason: Namespace DYLD, Code 1 Library missing
Library not loaded: /opt/homebrew/.../libssl.3.dylib
Referenced from: .../DBmind.app/Contents/MacOS/dbmind-desktop
```

## 原因

`dbmind-core` 用 `ssh2`（libssh2）做 SSH 隧道。libssh2 在 **Windows 上走 WinCNG**（系统 CryptoAPI），
所以 Windows 包从来不需要 OpenSSL；但在 **macOS / Linux 上它默认链系统的 OpenSSL** ——
CI 的 macOS runner 上那就是 Homebrew 装的那一份：

```
openssl-sys  →  libssh2-sys  →  ssh2  →  dbmind-core
```

于是打进包的二进制里留着一条 `/opt/homebrew/opt/openssl@3/lib/libssl.3.dylib` 的绝对路径。
你的机器上要么没有这个文件，要么它虽然存在、但 hardened runtime 的**库校验不认它的 Team ID** ——
两种情况都是同一句话：**链接期就欠了一笔，装到你机器上却还不上**。
之前几个版本一直是这么打的，只是没人在 Mac 上跑过。

## 改法

- **改静态链接**：unix（macOS / Linux）上给 `ssh2` 打开 `vendored-openssl`，
  由 `openssl-src` 从源码编一份 OpenSSL **静态链进二进制**。包内不再有任何外部 `.so` / `.dylib`，
  也就不再要求目标机器装过什么。Windows 不动（本来就不走 OpenSSL）。
- **加一道 CI 守卫**：macOS 产物出包后自动 `otool -L` 体检，
  一旦主可执行文件里出现 `/opt/homebrew` 或 `/usr/local` 下的动态库，**这一步直接失败** ——
  这类「在 CI 机器上能跑、到用户机器上必崩」的包不会再发出去。

## 安装包（全平台）

| 平台 | 文件 | 形态与适用场景 |
|---|---|---|
| Windows | DBmind_1.2.1_x64-setup.exe | 安装向导（推荐） |
| Windows | DBmind_1.2.1_x64_en-US.msi | MSI 包（企业批量部署 / 静默安装） |
| Windows | dbmind-1.2.1-portable.zip | **免安装**：解压即用，不写注册表 |
| macOS（Apple 芯片） | DBmind_1.2.1_aarch64.dmg | 安装镜像：拖进「应用程序」 |
| macOS（Intel） | DBmind_1.2.1_x64.dmg | 安装镜像：拖进「应用程序」 |
| Linux（Debian / Ubuntu） | DBmind_1.2.1_amd64.deb | apt 安装，带开始菜单项 |
| Linux（通用发行版） | DBmind_1.2.1_amd64.AppImage | **免安装**：`chmod +x` 后直接运行 |

- 每个包都自带精简 Java 运行时（目标机器不必另装 Java），macOS 版**不再需要 Homebrew 的 OpenSSL**。
- 未配置签名证书：macOS 首次打开需到「隐私与安全性」放行，Windows 会提示「未知发布者」。

## 升级提示

- **装过 v1.2.0 的 macOS 用户请直接换这一版**（v1.2.0 的 mac 包是打不开的）。
- Windows / Linux 用户：功能与 v1.2.0 完全相同，可以不升；升了也没有副作用。
- 无破坏性变更，连接、脚本与设置全部保留。
