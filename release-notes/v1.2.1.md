# v1.2.1

> 修一个会让 macOS 版**双击就打不开**的问题；顺带把 macOS 图标按 Apple 的网格重做、并给 DMG 加上「拖进应用程序」的布局声明

发布日期：2026-10-10
类型：修订版（无新功能、无破坏性变更，建议所有 macOS 用户升级）

## 修掉 macOS 打不开

**症状**：macOS（实测 M1）双击 `DBmind.app` 立即退出，系统弹「问题详细信息」，关键几行是：

```
Termination Reason: Namespace DYLD, Code 1 Library missing
Library not loaded: /opt/homebrew/.../libssl.3.dylib
Referenced from: .../DBmind.app/Contents/MacOS/dbmind-desktop
```

**原因**：`dbmind-core` 用 `ssh2`（libssh2）做 SSH 隧道。libssh2 在 **Windows 上走 WinCNG**
（系统 CryptoAPI），所以 Windows 包从来不需要 OpenSSL；但在 **macOS / Linux 上它默认链系统的 OpenSSL** ——
CI 的 macOS runner 上那就是 Homebrew 装的那一份（`openssl-sys → libssh2-sys → ssh2 → dbmind-core`）。
于是打进包的二进制里留着一条 `/opt/homebrew/opt/openssl@3/lib/libssl.3.dylib` 的绝对路径：
你的机器上要么没有这个文件，要么它虽然存在、但 hardened runtime 的**库校验不认它的 Team ID** ——
两种情况都是同一件事：链接期欠了一笔，装到你机器上却还不上。

**改法**：unix（macOS / Linux）上给 `ssh2` 打开 `vendored-openssl`，由 `openssl-src` 从源码编一份
OpenSSL **静态链进二进制**。包内不再有任何外部 `.so` / `.dylib`。Windows 不动（本来就不走 OpenSSL）。

**证据**（本次 CI 的 macOS 作业里，对成品 `.app` 跑 `otool -L`）：

```
== otool -L .../DBmind.app/Contents/MacOS/dbmind-desktop
OK：没有 /opt/homebrew、/usr/local 下的动态依赖
```

## macOS 图标：不再比邻居「大一圈」

- 原因：`icons/` 里原来只有 `icon.ico`（Windows）与一张 **满幅** 的 `icon.png`（256×256），
  **没有 `.icns`**。而 macOS 的图标网格要求画面只占画布约 **80%**、四周留透明边 ——
  画面铺满的图标放进 Dock / Finder，视觉上就会明显压过旁边的 App。
- 现在：新增 `scripts/make-macos-icns.ps1`，把画面缩到 80.5% 居中放进透明画布，
  并按 macOS 需要的档位（`ic07`…`ic14` + `icp4`…`icp6`）生成 `icon.icns`。
  Windows 的 `icon.ico` **不动** —— Windows 图标本来就是满幅的。
- 说明：素材最大只有 256×256，512/1024 两档是放大出来的（会偏软）。
  拿到 1024×1024 的原始图后，重跑那个脚本就能得到更锐的图标。

## DMG：明确「拖进应用程序」

- `tauri.conf.json` 的 `bundle.macOS.dmg` 显式写上窗口尺寸与两个图标的位置
  （App 180,180 / 应用程序 480,180），把拖拽布局固定下来。
- 成品 DMG 挂载后确实带软链（本次 CI 实测）：

```
挂载点 = /Volumes/DBmind
lrwxr-xr-x  Applications -> /Applications
```

- 已知（非本次引入）：CI 上 Tauri 会给打包脚本传 `--skip-jenkins`，跳过设置**背景图与图标位置**的
  AppleScript，所以 DMG 窗口是朴素的白底、两个图标由 Finder 自动排列 ——
  **拖拽安装本身可用**，只是没有那种定制的背景与箭头。要那种效果需要绕开这个开关另行处理。

## CI 加了两道守卫

- **macOS 依赖体检**：出包后对主可执行文件跑 `otool -L`，一旦出现 `/opt/homebrew` 或 `/usr/local`
  下的动态库就**直接失败** —— 上面那类「在 CI 能跑、到用户机器必崩」的包不会再发出去。
- **DMG 布局体检**：把 DMG 挂起来列出根目录，确认里面有指向 `/Applications` 的软链。
