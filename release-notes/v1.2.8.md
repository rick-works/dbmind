# v1.2.8

> 三处「看得见」的修复：在线更新按你的系统挑包（苹果版不再下到 exe）、NoSQL 预览与 NULL 的对齐统一、深色下未保存提示条不再刺眼；外加 macOS 安装页的排版

发布日期：2026-10-11
类型：修订版（无破坏性变更）

## 在线更新：按你的系统挑安装包（请务必升级）

更新器原先只按文件后缀打分（`-setup.exe` 3 分 > `.msi` 2 分 > `.zip` 1 分），**完全没有平台概念** —— 于是任何平台都挑中分数最高的那个 Windows 安装包：**苹果版点「在线更新」，下回来的是一个 exe，装了也起不来。**

现在先按平台过滤，再在同一平台的包里挑：

| 平台 | 优先 | 兜底 |
|---|---|---|
| Windows | `-setup.exe` | `msi` → 绿色版 `zip` |
| macOS（Apple 芯片） | `*aarch64.dmg` | 不带架构名的通用 dmg |
| macOS（Intel） | `*x64.dmg` | 同上 |
| Linux | `deb` | `AppImage` |

不匹配本机平台的包一律 0 分，架构也反了（M 芯片拿到 Intel 包）同样不选；确实没有合适的包时，界面只给「前往下载页」，而不是塞一个装不上的文件。

**这个修复要先手动装上一版才生效**：bug 在**已发布的客户端**里（v1.2.7 及更早），所以苹果版的在线更新要等到装上本版之后，才会自己挑 dmg。**本版请先手动下载 dmg 安装。**

## 对齐口径：三个网格重新统一

- **NoSQL 预览**（Mongo / Redis）原先没有任何对齐规则，一律左对齐 —— 同屏对比另外两个网格（数字都靠右）就显得各行其是。现在接同一套 Excel 规则：**数字 / 日期靠右、布尔居中、文本靠左**。NoSQL 的文档没有字段类型，所以完全看这一列的值怎么排。
- **NULL 跟同列的真值对齐**。以前 NULL 只查字段类型，而两个来源都靠不住：SQL 结果集常常拿不到列类型；`CHAR` 列里又存着 `02301` 这类「类型说文本、值像数字」的编码。于是同一列里出现**「数字靠右、NULL 靠左」**。现在 NULL 按这一列的多数派走，与真值一致。
- 顺带补上 NoSQL 里漏掉的 NULL 样式（灰 + 斜体）—— 之前它的 NULL 和普通文本长得一模一样。

## 观感与安装页

- **深色模式**：「有未保存的修改」提示条原用了 Element 浅色主题的色阶（`--el-color-warning-light-9`），而本项目深色是默认主题、并未引入 Element 的深色变量表，于是深色下就它亮成一片浅黄。改用主题令牌 `--dc-warning-wash`，两种主题都合适。
- **macOS 安装页排版**：窗口位置改为**居中**（按 1440×900 的逻辑分辨率算 `(390, 230)`），窗口加高到 440 —— 之前说明书那一行放在窗口底缘，**文件名整条被裁掉、看不见**。
- **DMG 说明书**：补上「已经装进应用程序、双击还是被拦」的一条命令（`xattr -dr com.apple.quarantine /Applications/DBmind.app`），等价于翻系统设置那三步但不用翻。

## Linux 用户注意（我们没有 Linux 机器，这两条是照着依赖写的）

- **`.deb`**：`sudo apt install ./DBmind_1.2.8_amd64.deb`；提示缺依赖时补一句 `sudo apt -f install`。它依赖 `libwebkit2gtk-4.1`，所以 **Ubuntu 22.04+ / Debian 12+** 直接装；更老的发行版只有 4.0 那套，需要自行处理。
- **`.AppImage`**：先 `chmod +x`。它需要 **libfuse2**，而 Ubuntu 22.04 起默认只带 fuse3 —— 如果双击没反应，`sudo apt install libfuse2`，或者免挂载直接解包跑：`./DBmind_1.2.8_amd64.AppImage --appimage-extract-and-run`。
- CI 每次都会在 Ubuntu 22.04 上把 `.deb` 与 `.AppImage` 打出来（AppImage 的打包本身就是跑一次 linuxdeploy）；但**真机运行**只能靠反馈，装的时候有任何报错都发给我们。
