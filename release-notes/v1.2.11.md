# v1.2.11

> 「在线更新」修好了：Windows 不再报「找不到文件」，macOS 更新完会正常挂载安装镜像 —— 顺带把安装包保存位置显示出来

发布日期：2026-10-11
类型：修订版（无破坏性变更）

## 修好了：下载完成却拉不起安装器

上一版（1.2.9 / 1.2.10）在 Windows 上点「在线更新」，下载其实是成功的，接着却会弹一句
「Windows 找不到文件 …\DBmind_x.y.z_x64-setup.exe」—— 而那个文件就好好躺在下载目录里
（实测 46.9 MB、sha256 与 GitHub 官方 digest 完全一致、文件名里也没有任何隐形字符）。

原因是 1.2.9 里换了一种拉起方式：`cmd /C start` 并且**手写了引号**。手写的引号会被 Rust 的
参数转义再包一层（`"…"` → `\"…\"`），而 cmd.exe 对 `\"` 的解析跟系统创建进程那套规则不一样，
路径被拆坏，于是系统报「找不到文件」。现在**不再经过 cmd**，直接创建进程起安装包 ——
转义按系统规则做，路径带空格也正确。

macOS 那边是另一处问题：`open` 只用「进程有没有起来」判断成败，而它自己失败时（文件不在、
被系统策略拒绝）是**退出码非 0** —— 于是界面说「安装向导已启动」、实际什么都没发生，
这正是"更新完没弹出安装"的由来。现在会等它返回、看退出码，失败就如实报（Linux 的 `xdg-open` 同理）。

## 更新完成时会告诉你装到哪了

完成提示里多了一行安装包的保存路径：

> 已保存到：C:\Users\你\Downloads\DBmind_1.2.11_x64-setup.exe（若没有自动打开，双击它即可安装）

万一自动打开被系统拦住（Windows 的 UAC、杀毒软件、macOS 的策略都可能），照着这句话双击
那个文件就能装，不必再去翻下载目录。另外拉起之前会先确认文件**真的落地了** ——
没落地就直说"没落到哪"，而不是拿一个不存在的路径去拉、让系统弹错。

## Linux 用户注意

- `.deb`：`sudo apt install ./DBmind_1.2.11_amd64.deb`；提示缺依赖时补一句 `sudo apt -f install`。它依赖 `libwebkit2gtk-4.1`，所以 Ubuntu 22.04+ / Debian 12+ 直接装。
- `.AppImage`：先 `chmod +x`。它需要 **libfuse2**（Ubuntu 22.04 起默认只带 fuse3）—— 双击没反应就 `sudo apt install libfuse2`，或者 `./DBmind_1.2.11_amd64.AppImage --appimage-extract-and-run` 免挂载运行。
- 托盘图标在 Linux 上依赖 **libayatana-appindicator**（deb/AppImage 会带上运行时）。我们没有 Linux 机器，这一项**没能真机验证**，装的时候若有问题请反馈。
