## 更新说明

- 修复 SQL Server / PostgreSQL 上「选定了模式」的整库同步整批失败：目标库其它模式（如 dbo）里有同名表时，每张表都被判成「删除目标表失败」（`Cannot drop the table 'test.X', because it does not exist`）。目标侧结构改为只按选中的模式查询，删除语句统一带 `if exists`
- 修复数据对比在大表上结果错乱：超过 10 万行、转落盘比对之后，从第 2 行起每一行都错位，整批报「未知的对比单元格类型 10」；现在大表与小表结果一致
- 修复 Oracle / 达梦上以日期时间列作比对键的报错：第 2 页（5 万行之后）会 ORA-01861 / ORA-01843，原因是字符串按会话 NLS 格式隐式转换；游标改用 ANSI `timestamp` 字面量，会话设置不再影响，字符串列里存的 ISO 时间仍按字符串比较
- 修复 Oracle / 达梦上带引号建的小写列名做对比报 ORA-00904：列名一律按库里真实大小写逐字加引号
- 「开始对比」不再先干等 `count(*)`：大表上数一遍要几十秒到几分钟，而它只用来画进度条；现在最多等 10 秒，超时就以流动进度条开始比对
- 修复一个会打挂进程的判断：目标侧行数统计失败（超时 / 无权限）被当成 0，几千万行的表因此被当成「小表」整表装进内存；分母不可信现在一律走落盘
- 点「停止」不再丢掉已经比出来的结果：已读取的部分会保留并标注「以下只是已读取部分的对比结果」；停止也从「等当前分片跑完」变成即时响应
- 失败 / 中断的原因直接显示在进度窗口（以前只弹 3 秒提示，来不及看就没了）；从任务中心恢复的对比任务也不再缺历史日志
- 百万行级对比的落盘写入提速：每行 3 次异步写改为 128 KB 缓冲批量落盘
