# v1.2.12

> 修好了「点了没反应」的关闭询问（三个平台）；在线更新改成一键静默升级：点一次，应用自己装好并自动重启

发布日期：2026-10-11
类型：修订版（无破坏性变更）

## 修好了：点「关闭 / 最小化到托盘」没反应

上一版（1.2.10 / 1.2.11）里，点右上角 × 会正常弹出「关闭 DBmind?」，但**两个按钮点了都没反应** ——
窗口既不关掉、也不收进托盘，只能从托盘菜单退出。三个平台（Windows / macOS / Linux）都一样。

原因出在 Tauri 的权限机制上：这个询问是"桌面壳 → 页面弹窗 → 页面回话"的一次往返，而回话要调壳自己的命令；
Tauri v2 **只对"来自非本地来源"的请求做 ACL 检查**，而本应用的前端是从 `http://127.0.0.1:<端口>`
加载的（内核在本地起着 HTTP 服务），在它眼里正属于"非本地"。于是：

- 「壳 → 页面」的**事件**不走 ACL → 询问弹窗照常出现；
- 「页面 → 壳」的**命令**被 ACL 拒绝 → 两个按钮都毫无反应。

修复就是给这条命令补一份权限声明（再在 capability 里引用）。另外把它"藏不住"了：此前这类失败只写进
页面标题，而页面改标题并不会改原生窗口标题，外部完全看不到原因 —— 现在会如实写到窗口标题上。

## 在线更新：点一次就完事

以前点「立即更新」是下载完拉起**安装向导**，剩下几步要用户自己点。现在：

点「立即更新」→ 后台静默下载（有进度）→ 显示「下载完成，正在安装更新」→ 应用**自己退出** →
**静默安装**（没有向导、没有窗口）→ 几秒后**新版自己打开**。

- **Windows**：安装器跑静默模式，原地覆盖 —— 安装目录沿用上一次的，不算新装，设置与连接都留着
- **macOS**：不再"挂上镜像让你自己拖"。自动挂载、把新的 app 覆盖到原位置，并**去掉「从网上下载」的
  隔离标记** —— 新版首次打开不用再去「隐私与安全性」手动放行（那正是更新里最别扭的一步）
- **Linux** 仍按原来的方式（deb / AppImage 交给桌面环境）

顺带堵了一个不显眼的坑：安装器为腾出文件锁会**强杀**正在运行的应用，而强杀不会走应用的退出流程，
清理后台 java 宿主那一步就不会执行 —— 那些 java 会变成孤儿留在后台占内存。现在应用会在开装前
**优雅退出**，清理照跑，随后由安装器接管。

## Linux 用户注意

- `.deb`：`sudo apt install ./DBmind_1.2.12_amd64.deb`；提示缺依赖时补一句 `sudo apt -f install`。它依赖 `libwebkit2gtk-4.1`，所以 Ubuntu 22.04+ / Debian 12+ 直接装。
- `.AppImage`：先 `chmod +x`。它需要 **libfuse2**（Ubuntu 22.04 起默认只带 fuse3）—— 双击没反应就 `sudo apt install libfuse2`，或者 `./DBmind_1.2.12_amd64.AppImage --appimage-extract-and-run` 免挂载运行。
- 托盘图标在 Linux 上依赖 **libayatana-appindicator**（deb/AppImage 会带上运行时）。我们没有 Linux 机器，这一项**没能真机验证**，装的时候若有问题请反馈。

## 升级提示

- 无破坏性变更：连接、脚本与设置全部保留；Web 版（浏览器里打开）行为完全不变。
- **这次更新时，你看到的还是老流程**（会弹安装向导）—— 因为跑的是你机器上**旧版客户端**的逻辑。
