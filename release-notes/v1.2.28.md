## 更新说明

- 修一个我自己引入的回归：处理 Oracle 的问题时加的「元数据预热」忘了只给 Oracle，所有数据库的每个新会话都在付这笔账（跨库找一张不存在的表）—— 树展开一次要建几十个会话，表现出来就是「所有库展开都变慢、编辑表结构转半天」。现在预热只在 Oracle 上做
- ClickHouse 的建连从 2.4 秒回到 0.1 秒级：驱动默认走的 Apache HttpClient 路径在 Windows 上每次建连固定多 2 秒以上，换成驱动自带的 URLConnection 路径（实测取列 2.9 秒 → 0.2 秒）
- 编辑表结构页也挂上只读 / 生产环境的常驻提示条（与用户管理页同一形态）：只读连接或标注为生产的库，进页面就知道保存会被拦下，而不是改完点「保存修改」才被拒
