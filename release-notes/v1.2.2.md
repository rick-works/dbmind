# v1.2.2

> macOS 版的两个真问题：**打开是一片黑**（打包进去的资源没被找到）、**DMG 安装页不像"拖进应用程序"**；另有一件需要证书才能彻底解决的事写在最后

发布日期：2026-10-11
类型：修订版（无新功能、无破坏性变更，建议所有 macOS 用户升级）

## 修掉「打开是黑屏」

**症状**：macOS 上装好后打开，窗口在、菜单栏在，但界面**一片黑**。

**原因**：程序按「可执行文件旁边」找打包进去的资源（前端产物 `web/`、宿主 jar `agents/`、
自带运行时 `jre/`）—— 这在 Windows 上成立（便携版与安装包都把资源放在 exe 同级），
但 macOS 的 `.app` 里 exe 在 `Contents/MacOS/`、而资源在 **`Contents/Resources/`**：

```
DBmind.app/Contents/MacOS/dbmind-desktop        ← 可执行文件
DBmind.app/Contents/Resources/web/              ← 前端产物（没被找到）
DBmind.app/Contents/Resources/agents/*.jar      ← 宿主 jar（没被找到）
DBmind.app/Contents/Resources/jre/bin/java      ← 自带运行时（没被找到）
```

找不到前端产物时，内嵌服务只提供 API、页面就是空的 —— 代码里那句日志写的正是这个意思：
「没找到前端产物：内嵌壳只提供 API，页面会是白页」。

**改法**：新增 `dbmind_core::paths::app_resource_roots()`，把各平台打包后的资源目录统一列出来
（Windows 在 exe 旁、macOS 在 `Contents/Resources/`、Linux 在 `usr/lib/<产品名>/`，AppImage 还认 `$APPDIR`），
`web/`、`agents/`、`jre/` 三处一律经它查找：

- 前端产物探测（`dbmind-web`）→ 黑屏消失
- 宿主 jar 解析（`dbmind-core`）→ MySQL / MongoDB / Redis / ES / JDBC 不再一律"驱动未就绪"
- 自带运行时探测（`dbmind-desktop`）→ 不再报「没找到 Java 17+」

顺带修掉一个**只在 macOS / Linux 上成立**的低级错误：java 可执行文件名原先写死 `java.exe`，
而这两个平台上它叫 `java` —— 等于自带 JRE 形同虚设；系统查找也一并按平台区分，
Windows 专有的安装目录（`C:\Program Files\Java` 等）收进 `cfg!(windows)` 分支。

## DMG 安装页：现在是正经的「拖进应用程序」

Tauri 在 CI 上会给打包脚本传 `--skip-jenkins`，**跳过**"设置窗口背景与图标位置"的 AppleScript
（headless runner 上 Finder 自动化不可靠）—— 于是 DMG 打开就是两个图标堆在左上角、没有留白与动线，
用户的原话是「安装的页面不对」。

现在改用 **dmgbuild**：它自己写 `.DS_Store`、不经过 Finder，所以能在 CI 上跑出正常布局 ——
左边 `DBmind.app`、右边「应用程序」软链，窗口 660×400，图标按预设位置摆放。
（有背景图会让"拖过去"更直观，这个还没做，见文末。）

## 还是想「不执行那条 sudo 命令就能打开」？

那条命令是：

```bash
sudo xattr -dr com.apple.quarantine /Applications/DBmind.app
```

它去掉的是 macOS 给"从网上下载的文件"打的**隔离标记**。没有它，系统会对未签名/未公证的 App
弹「无法验证开发者」—— 这是 macOS 的既有规则，**不是应用能自己绕过的**。
右键 →「打开」（或在「隐私与安全性」里点「仍要打开」）可以放行一次，但这终究是额外一步。

要做到"下载完双击就能开"，只有一条路：**Apple 开发者证书（99 美元/年）+ 公证（notarization）**。
打包流程这边**已经准备好了** —— `.github/workflows/release.yml` 支持从仓库 Secrets 读
`APPLE_CERTIFICATE` / `APPLE_CERTIFICATE_PASSWORD` / `KEYCHAIN_PASSWORD`，配齐后自动签名；
再配上 `APPLE_ID` / `APPLE_PASSWORD` / `APPLE_TEAM_ID` 就自动公证。缺证书时现走的是
ad-hoc 签名兜底（Apple 芯片上至少保证能跑起来），这也是为什么现在还需要那一步手动放行。

## 安装包（全平台）

| 平台 | 文件 | 形态与适用场景 |
|---|---|---|
| Windows | DBmind_1.2.2_x64-setup.exe | 安装向导（推荐） |
| Windows | DBmind_1.2.2_x64_en-US.msi | MSI 包（企业批量部署 / 静默安装） |
| Windows | dbmind-1.2.2-portable.zip | **免安装**：解压即用，不写注册表 |
| macOS（Apple 芯片） | DBmind_1.2.2_aarch64.dmg | 安装镜像：把图标拖进「应用程序」 |
| macOS（Intel） | DBmind_1.2.2_x64.dmg | 安装镜像：把图标拖进「应用程序」 |
| Linux（Debian / Ubuntu） | DBmind_1.2.2_amd64.deb | apt 安装，带开始菜单项 |
| Linux（通用发行版） | DBmind_1.2.2_amd64.AppImage | **免安装**：`chmod +x` 后直接运行 |

- 每个包都自带精简 Java 运行时（目标机器不必另装 Java）。
- 未配置签名证书：macOS 首次打开需右键「打开」或在「隐私与安全性」放行，Windows 会提示「未知发布者」。
