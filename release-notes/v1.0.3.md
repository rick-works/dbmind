# v1.0.3

> ClickHouse 的两个坑一起填了 —— 这版之后，表数据浏览和 SQL 查询都能正常出数、也能出总条数

发布日期：2026-10-09
类型：修订版（修问题，不影响已有用法）

## ClickHouse

- **点开一张两千多行的表不再"执行失败"**：程序为了知道"还有没有下一页"，取数时会多要一条，
  而 ClickHouse 把"只取前 N 条"理解成了"超过 N 条就整条报错"—— 表里行数一多，点开就是一条失败。
  现在改成"取到上限就停下，并提示已截断"，和 MySQL / Doris / SQL Server 这些类型的表现一致。
- **另一个莫名其妙的报错也一起消失了**：那种提示「读取布尔值失败」的报错，其实是同一处问题的另一面
  —— 以前为了绕开上面那个限制干脆不设上限，服务端于是把整张表（实测 237 万行）一起推下来，
  读的过程中就出错了。现在上限照设，数据也少拉了很多。
- **总数不再显示 -1**：ClickHouse 返回的计数是小数，程序以前只认整数，取不到就等于"统计不出来"，
  所以界面上永远看不到总条数（「总数统计中…」一闪就没了）。现在各种数字形态都认，
  与左侧树上的表行数、质量规则的违规数口径一致。

## 编辑器

- **选中一段 SQL 点「格式化」不再报错**：以前会弹「t is not a function」。同一处写法还影响到了
  「大写 / 小写 / 单行」转换、「复制为 IN 列表」、「复制为单行」（右键菜单与快捷键各一处），一并修好。
- **关键字排版「前换行」不再多断一行**：以前选「前换行」，实际效果是上下都换行；现在就是
  `FROM users u`。「前换行 + 缩进」「前后各换行」「后换行」等其余选项的行为保持不变。
