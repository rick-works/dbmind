修复打包第 2 步：构建前端时被「安全删除」闸门拦下（release.bat 在 IDE 终端里必挂）

现象：从 IDE 的终端跑 scripts\release.bat，第 2/8 步就失败：
  [plugin vite:prepare-out-dir]
  Error: [safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":589,"threshold":500,...}
  at checkBulkDeleteGuard (...\extensions\genie\out\vendor\shim\node-safe-delete-shim.cjs:404)

原因：IDE 终端会给 Node 注入一层安全删除 shim（删除先进回收站，且「单轮删除超过 500 个文件」
      要先确认）。而 Vite 每次构建都要清空 frontend\dist（assets 有近 200~600 个文件），
      于是必然撞上这个闸门 —— 与 DBMind 的代码无关，换一个普通终端跑就正常。

改动：release.ps1 第 2 步里，构建前先自己把 frontend\dist 清掉（用 .NET 的
      Directory.Delete 直接删目录树 —— 删的是构建产物，本来也不该进回收站）。
      之后 Vite 面对的是一个不存在的目录，谈不上「批量删除」，闸门自然不会触发。
      清空失败只告警、继续交给 Vite 自己清，不会让打包因此中断。

验证（原样复现 + 对照，两边都实测）：
  先造 600 个探针文件，使 frontend\dist 达到 793 个文件
  A 直接 npm run build      → ✗ 复现同样的报错
                              [safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] count=793 threshold=500
  B 跑 release.ps1 第 2 步   → ✓ 已清空 frontend\dist → built in 2.10s →
                              OK frontend\dist 7 MB，退出码 0
  探针文件全部清掉，dist 回到 193 个文件。
