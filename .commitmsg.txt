全项目导出统一为「用户自己选保存位置」+ 修掉整库转储 xlsx 打不开的 bug

一、所有导出/下载入口统一（共 11 处）
新增通用核心 saveBlobAs(blob, 完整文件名)：弹系统另存为（File System Access API），
拿不到就退回普通浏览器下载。saveExportBlob 也改成委托它。
改造的入口：
  useExportTask（异步导出全部：导出前先挑位置）
  TableDataView / SqlQueryView（导出当前页）
  DataSourcePicker（连接导出 JSON）
  AiPanel（AI 文档导出）
  QualityAnalysisPanel（分析结果导出）
  DataPivotDialog（透视表导出 CSV）
  ErDiagramView（ER 图导出 svg/png）
  NoSqlDataView（NoSQL 导出 CSV）
  connTransfer（连接迁移导出 JSON）
现在整个前端只剩 useExportTask 里【一处】兜底的 <a download>，其余全走用户选位置。

二、检查所有导出格式时抓到一个真 bug：整库转储导出的 Excel 打不开
export.rs 转储分支里，xlsx 是"先写进内存再塞进 zip"，但那个 sink 从没调用 finish()——
而 [Content_Types].xml / workbook / 关系 / 样式这些容器部件恰恰是在 finish() 里补写的。
结果包内的 products.xlsx 只有一个孤零零的 worksheet 流，Excel 打开会说文件损坏。
（普通导出那条路有调 finish，只有整库转储这条一直漏着。）
已补上 sink.finish()。

三、逐个格式实测（table=products，page=1 size=50）
  csv            BOM=True ✓ 行数=52 ✓ 表头正常 ✓
  json           可解析 ✓ 50 条 ✓
  excel          OPC ✓ 关系目标存在 ✓ sheet XML 良构 ✓ 行数=51 ✓
  sql-insert     insert into products (…) ✓
  sql-update     update products set … ✓（需带 pkColumns）
  sql-delete     delete from products where product_id = 1; ✓
  ddl            CREATE TABLE `products` (…) ✓
  整库转储 excel  包内 products.xlsx → OPC ✓ 关系 ✓ XML 良构 ✓ 行数=217（216 行数据+表头）✓
  整库转储 sql    含 CREATE TABLE ✓ INSERT INTO ✓ DROP TABLE ✓

说明：sql-update / sql-delete 不带主键时后端会拒绝（400），这是**故意**的 ——
没有主键就会生成 where 1=1 式的更新/删除语句，宁可不错。
