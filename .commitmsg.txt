修复：SQL 末尾带分号时统计总数失败（界面因此一直显示「未统计总数」、没有「共 N 条」）

根因：统计与分页套壳用的是**原样 SQL**。用户（和前端）的 SQL 十有八九带分号：

  SELECT * FROM `sales`;

- 统计被拼成  select count(*) as cnt from (SELECT * FROM `sales`;) dbmind_count
  —— 分号在子查询里是语法错误 → count 失败 → 退出码走 None → totalCount 保持 -1
- 同理 page > 1 套分页壳也会拼出同样的非法子查询 → 翻页也会报错

我之前把导出里的 base_sql 做法照搬过来时漏了一点：base_sql 内部会
trim_end_matches(';')，而我在 query.rs 里直接用了原始 SQL。

改动：套壳与统计改用「去掉末尾分号」的版本（执行仍用原样 SQL，
避免影响多语句/DDL 的语义）。

验证（在真实浏览器里，同源同参，SQL 带分号）：
  第 1 页 → totalCount=205106  rowCount=200  hasMore=true
  第 2 页 → totalCount=205106  rows=200  firstId=202  lastId=401
界面实测（截图 target/verify-paging.png）：
  底栏「共 205106 条」、页码 1..1026、“已返回 200 行（未统计总数…）”消失

教训：我先前用 API 直接验证时用的是**不带分号**的同句 SQL，于是两次都测不出来，
还把用户的「还是老样子」误判成浏览器缓存。验证必须与真实输入完全一致 —— 这次是靠
自己开浏览器（agent-browser）在页面里发同源请求才定位到的。
