修复：SQL 末尾带分号时，条数不显示、翻页失效

根因不在后端（后端已能返回 totalCount 与正确分页），而在前端的切句：
SELECT * FROM `sales`; 这种末尾带分号的写法会多切出一段「空语句」，
于是「一条语句」被算成「多段」，调用方按段数选链路：

  段数 > 1 ⇒ executeSqlBatch  ⇒ 批量接口：不传 page/size，后端也不统计总数
  段数 = 1 ⇒ executeSql       ⇒ 单条接口：带 page/size，能翻页、能显示「共 N 条」

所以界面看到的正是「条数没了 + 翻页也没了」。这也解释了为什么我用 API 直连
（SQL 不带分号）测一直是好的：两边只差一个分号。

改动：splitSqlStatements 过滤空白段（只有这一处判定用段数选链路，
其余真实多段脚本如 SELECT 1; SELECT 2 仍走批量，行为不变）。

用 node 直接跑该函数实测 10 例，全部符合预期：
  SELECT * FROM `sales`;   → 1 段 ✓（修前是 2 段）
  SELECT * FROM `sales`    → 1
  SELECT 1;                → 1
  SELECT 1; SELECT 2       → 2
  SELECT 1; SELECT 2;      → 2
  SELECT 1;\n\n            → 1
  ;  /  '  ;;  '           → 0
  SELECT 1; -- 注释\n; SELECT 2;  → 2
