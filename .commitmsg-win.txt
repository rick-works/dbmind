修 SQL Server「Windows 验证」：Windows 上改用原生 SSPI，并把认证库按驱动版本就位

问题：选「Windows 验证」连本机 SQL Server，弹窗报
  [DBMIND-CONN-0003] 连接失败：集成身份验证失败

实测定位（三步，别凭印象改回去）：
  A. 当前代码在 Windows 上也用 authenticationScheme=JavaKerberos（agent.rs 里写明"纯 Java、
     不需要平台原生 DLL"）—— 但 Kerberos 要先 kinit 拿到票据，本机 SQL Server（无域）必然失败，
     报的就是「集成身份验证失败」。
  B. 换成 integratedSecurity=true;authenticationScheme=NativeAuthentication +
     java.library.path 指向按驱动版本命名的 mssql-jdbc_auth-12.8.1.x64.dll → 立刻连上
     （SQL Server 15.00.2000，dbUser=RICK\Rick）。
  C. 同一个 dll 不改名（还是 12.6.1）→ 报「没有为集成身份验证配置驱动程序」：
     驱动是按 System.loadLibrary 里的**文件名版本号**找它的。
  另外：那份 dll **不在驱动 jar 里**（本仓的 mssql-jdbc-12.8.1.jre11.jar 里 0 个 dll）。

改动：
1. agent.rs `render_jdbc_url`：Windows 上用 NativeAuthentication（当前登录身份，不要票据），
   其它平台没有 SSPI，仍走 JavaKerberos。
2. agent.rs 新增 `ensure_native_auth_library` / `auth_library_names` / `native_arch`：
   驱动目录里只要有一个同架构的 `mssql-jdbc_auth-*.dll`，就按**当前驱动版本**（从目录里的
   mssql-jdbc-<版本>.jar 名字上读，不依赖 manifest）复制改名到 <驱动目录>/auth/。
3. agent.rs `ensure_process`：spawn 宿主之前扫一遍驱动目录，备好认证库并把该目录加进
   `-Djava.library.path`（只在 JVM 启动那一刻生效；显式设置会替换默认库路径，故一并带上
   System32）。扫驱动目录而不是 spec.agent_keys —— SQL Server 由通用宿主承载，后者是空的，
   按 spec 扫会安静地一个都不问（这一点我第一版就写错了，已改）。
4. agent_driver.rs：连接前拦一道，缺库时直接给出"要哪个文件名、放哪个目录、要重启"，
   而不是把驱动那句「没有为集成身份验证配置驱动程序」原样丢给用户。
5. 文案：cd.windowsAuthHint 改成"Windows 上用当前登录账号（原生 SSPI，无需域/票据）；
   Linux/macOS 走 Kerberos 需 kinit"（中英同步）；SettingsView 里那条过期注释顺手改对。

验证：
  · cargo check 干净；新增/更新的两个单测通过（dll 文件名规则、Windows 认证 URL）
  · 端到端（未保存的表单配置走 /api/sqlserver/test）：success=true，
    URL 为 ...;integratedSecurity=true;authenticationScheme=NativeAuthentication，
    服务端版本 Microsoft SQL Server 15.00.2000；启动日志显示认证库按驱动版本就位
  · 前端构建 + guard 通过
