存储收口（一）：AI 设置 / 用量账本 / 审计日志 从 json 文件搬进 dbmind.db

背景：后端状态散在 ~/.dbmind 下的 json 文件里（ai-config.json / ai-usage.json /
ai-audit.log / …），备份容易漏、查不动、清理也不方便。这次把它们收进主库。

内核（dbmind-core）：
- SCHEMA 新增 5 张表：ai_settings（单行）/ ai_models（按 ordinal 保序）/
  ai_usage_days / ai_usage_models（模型+日期两级）/ ai_audit（带时间索引）
- Store 新增方法：ai_settings / save_ai_settings（事务内整体替换）/ bump_ai_usage /
  ai_usage_days / ai_usage_models（SQL GROUP BY 汇总）/ import_ai_usage /
  insert_ai_audit / ai_audit_count
- 新增全局主库句柄 install_global_store / global_store：AI 这类"环境式"读写
  （对话管线深处要用，却与存储无关）按需取用，几十处函数签名一个都不用动。
  刻意不在 Store 构造里自动装 —— 单测会造大量内存库，自动装会互相串

Web（dbmind-web）：
- config.rs：load / save / record_usage / usage / audit 全部改走主库；对外 JSON 形状一字未变。
  用量汇总由"内存里把两层对象全遍历一遍"改成一条 GROUP BY（总 token 降序、并列按次数）
- 新增 api/ai/migrate.rs：启动时一次性导入老文件。三条规矩：幂等（库里没有才导）、
  导完把老文件挪到 backups/legacy-json/（否则用户在新界面删掉的数据会被老文件"复活"）、
  一样失败不牵连别样
- serve() 启动时装全局句柄 + 跑迁移

迁移对照（同一台机器，迁移前已在 backups/pre-migration/ 留底）：
  设置：enabled=True privacy=allow audit=False，1 个模型 z4ma85bv / deepseek-chat，
        baseUrl / maxTokens / embedding / hasKey 全一致；path 由 ai-config.json 变为 dbmind.db
  用量：4 天共 28 次（09-18=12 / 09-21=3 / 09-23=8 / 09-24=5）逐日一致；
        模型 deepseek-chat calls=7 totalTokens=12681 一致
  文件：ai-config.json / ai-usage.json 已移入 backups/legacy-json/，顶层只剩 dbmind.db
  幂等：再次重启迁移日志为 0 行，数据不变

仍留在文件里的（刻意不动）：prompts/*.md（要能直接用编辑器改）、drivers/*.jar（二进制缓存）、
exports/ backups/ work/（产物与流式临时文件）、logs/ 与 agent-hosts（进程 stderr / JVM 要文件路径）。
